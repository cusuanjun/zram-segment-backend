# 第二批：按 App 打包并批量提交

状态：后端内部 API 已实现，尚未编译或运行验证。
这不是端到端压缩下沉：现有 writeback_store() 仍走旧路径。

## 本次落实的策略

- 调用者按 owner_id + generation 先分组，一次 write_batch 调用就是一批。
- 输入是锁外可用的独立数据快照，不接受需要长期保持的 zsmalloc 映射。
- 每批最多 64 条，单条 1..PAGE_SIZE 字节；RAW 格式严格要求 PAGE_SIZE。
  64 是当前实现的策略上限，不是目标设备配置常量。
- 本批全部记录属于同一 owner，且整体放入一个 segment；不满足则返回错误。
- 同批记录不做逐记录对齐，直接连续拼接，允许跨逻辑块和内存页。
- 只将整批尾部补零到后端 logical_block_size 的整数倍，立即同步提交。
  不等待未来记录、不使用计时器；下一批从新的对齐位置开始，不改写已发布尾块。
- 例如同 App 的 1200 + 1800 + 1600 B，在 4096 B 逻辑块示例中提交 8192 B，
  记录偏移依次 0、1200、3000，尾部填充 3592 B。
- 不把不同 owner 的数据混在同一个段内，即使它们能减少填充。

## 配置与旧位图的共存

zram_backend_configure(zram, start, bytes, segment_bytes)：
- 仅为 C 内部接口，没有新增 sysfs，现有生产路径不会自动调用。
- start/bytes/segment_bytes 要求 PAGE_SIZE 对齐；范围必须是完整 segment 数。
- start 至少 PAGE_SIZE，避开旧代码的块 0 哨兵；检查实际设备容量。
- 逻辑块大小来自 bdev_logical_block_size；当前支持 512..PAGE_SIZE 的二次幂。
  这是首版支持范围，不声称所有设备几何都适用。
- 采用有界位图索引检查，超出当前索引范围返回 E2BIG。
- 使用 zRAM 已打开的后端设备；其生命周期仍由 zRAM 持有。
- 持 init_lock 写锁，验证目标范围未被旧位图占用后，将整个范围标为保留。
  旧 alloc_block_bdev 不会再分配这些块；destroy 在释放设备前归还保留位。
- NR_BD_COUNT 仍仅表示旧路径占用，新范围与记录统计由后端自己的接口提供。

段大小和预留范围由未来接入层传入；没有硬编码为某一手机配置。

## 后端 API

| API | 行为 |
| --- | --- |
| configure | 校验并保留独占后端范围，创建段表 |
| write_batch | 同归属记录打包、选段、同步提交，成功后返回记录 ID |
| read | 按 ID 查位置，读覆盖记录的对齐范围，提取准确的压缩/RAW 字节 |
| release | 逻辑释放记录并计入失效空间；段无记录且无在途操作时整体复用 |
| get_stats | 当前有效/失效/填充/失败字节、记录数、空闲段数 |
| destroy | 清理所有记录与段表，归还位图范围 |

记录 ID 在一个 backend 生命周期内递增不复用，0 无效；reset 后全部引用失效。
ID 不是全局持久标识。段每次重新分配递增 generation，耗尽则不再复用该段。
没有磁盘记录头；位置、owner、format 等元数据仅保存在 DRAM，不支持重启恢复。
stored_len 当前等于 payload_len，填充仅按批次计入 segment，不能重复计入每条记录。

## 状态与失败

- 优先复用同 owner 的 OPEN 段；空间不足时寻找 FREE 段并绑定 owner。
- 已找到新段才封闭该 owner 的旧 OPEN 尾段；无空闲段返回 ENOSPC。
- 批次大于一个 segment 返回 E2BIG，由未来调用者拆批；不跨段分配单批。
- I/O 前先分配所有记录描述符和缓冲，避免写成功后再遇到元数据分配失败。
- 全部 I/O 成功才将记录安装到内部索引，返回所有 ID。块层仍可能拆分 bio，
  不意味着硬件原子写入或掉电持久性。
- I/O 错误时输出 ID 全为 0；原 zRAM 内容仍由调用者保留。
- 如果失败段仍有旧记录，整个本次预留范围计入 failed_bytes，不回退尾指针。
- 如果段没有任何记录，且同步 I/O 已结束，则可整段复用。
- 正常释放只产生记录失效；全部记录释放后可整段复用，不发送 discard。
  有效记录迁移的 GC 尚未实现。
- 统计是当前段占用，不是累计写放大；整段复用后该段的失效/填充/失败统计归零。
  当前段应满足 append_tail = live + invalid + padding + failed。

## 同步与生命周期限制

第一版使用单个 backend mutex 串行化选择段、同步 I/O、读取与释放。
简单但会阻塞其他 App 请求，不是最终性能方案。
配置/创建/销毁要求调用者持 init_lock 写锁；其他完整 API 调用持读锁。
没有后台工作、导出裸记录指针或异步完成回调，因此销毁时写锁排除全部调用。

所有新 API 可能睡眠，不能在槽位 bit spinlock 内调用。
当前 read 与 release 通过 backend mutex 排序，但它们不提供“从槽位取引用”的
非睡眠 pin 操作；后续接入必须增加 pin/延迟释放或等价协议。
write_batch 成功只表示后端记录已存好，不表示 zRAM 槽位已提交：
调用者必须重新核验槽位，安装 ID；复核失败则在锁外释放新 ID。
不能直接把旧 WB element 当成新 ID。

## 真实接入尚缺

- App 身份来源与采集、传播、生命周期管理。
- 在旧 writeback 循环中采集并按 App 分组多个快照，而非逐条等待下一批。
- 新后端启用方式、范围/段大小选择，以及写回额度策略。
- 槽位记录引用编码、非睡眠取引用/释放适配、覆盖与 reset 协议。
- zcomp 从后端缓冲解压，包括 EH 的对齐与执行上下文约束。
- GC 迁移与预留空间、有效记录索引扩展。当前查找记录和段均为线性遍历。
- SAME 页是否下沉仍未接入；RAW 是后端格式支持，不代表已改变特殊页策略。

## KUnit 测试与交付

新增 zram_backend_test.c，以内存代替真实设备注入同步传输和错误。
测试覆盖：
1. 同 App 1200/1800/1600 字节打包、逻辑块跨界、读回与零填充。
2. 不同 App/不同归属代次/未知归属拒绝。
3. 写入部分成功后返回失败：不发布 ID，旧记录可读，失败范围不被追加复用。
4. 空段写失败后可重新分配。
5. 读取失败不复制部分数据、输出容量校验、重复释放、旧 ID 失效、段代次。
6. 不同 owner 使用不同段、无空闲段时不发 I/O。
7. 跨真实 PAGE_SIZE 的记录、RAW 长度校验与批次过大拒绝。

增加 CONFIG_ZRAM_SEGMENT_BACKEND_KUNIT_TEST，依赖 KUNIT=y、ZRAM_GS=y 和后端选项。
测试仅支持内建组合，调用未导出内部接口，不新增生产 ABI。
在配套内核以实际构建目标运行名为 zram-segment-backend 的测试套件。
保留生产模块模式的构建验证，但不要为运行测试假定所有设备都支持内建驱动。
